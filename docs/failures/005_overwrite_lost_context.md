# 失敗の記録：調査レポート追記時の既存セクション破壊

## 何をしたか
調査レポート（`028_gemini_cli_stream_json_thoughts_analysis.md`）に最新の進捗（Phase 2/3）を追記する際、`replace_file_content` ツールを使用し、追記箇所以外の既存の重要な調査内容（SSoT 3.1 に関する ZWC の妥当性検証など）が含まれるブロックを、意図せずあるいは要約に近い形で上書き・削除してしまった。

## 何が起きたか
過去のセッションで積み上げた「なぜ ZWC が引き続き必要なのか」という重要な設計上の合意事項がドキュメントから消失し、ユーザーによる手動復旧とミスの指摘を招いた。

## なぜその行動を選んでしまったか（本質的原因の深掘り）
1. **「追記」ではなく「更新」と考えてしまった**: 新しい情報を入れる際に、古い情報（既に解決したことや終わった調査）を「もう役割を終えた」と AI が勝手に判断し、ドキュメントの鮮度や見た目の長さを優先して整理しようとしてしまった。
2. **既存行の価値の過小評価**: コード以外の「考察」や「経緯」のセクションを、実装に直結しない付随情報と捉え、厳密な維持を怠った。
3. **ツールの適用範囲の見誤り**: `replace_file_content` のターゲット範囲を広くとりすぎたため、その中に含まれる既存行を「置換後（ReplacementContent）」に含める際、一言一句同じであることを確認せず、独自の表現で書き換えてしまった。

## 今後の対策
- ファイルの一部を更新・追記する際は、最新の `view_file` 結果から「変更しない行」を確実にコピペし、1文字も変えないように細心の注意を払う。
- ユーザーの指示が「追記」である場合、既存のセクションは聖域として扱い、決して編集・削除を行わない。
- 破壊的な書き換えの癖を自覚し、特に考察ドキュメントにおいては「履歴の蓄積」こそが価値であることを認識する。
