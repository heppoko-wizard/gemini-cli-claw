### 調査レポート：添付画像が認識されない問題 (Fact Finding Report)

【調査の道筋（仮説と検証のトレイル）】
- **仮説**: 最新メッセージに画像が含まれているはずなのに、アダプターがそれを認識できていない。
- **検証**: アダプターの `src/converter.js` および `src/server.js` のコードを精査。
### 3. OpenClawの画像認識・送信の解放条件（新規判明）
ウェブ調査およびコード調査の結果、OpenClawが画像を処理して送信するためには以下の条件が必要であることが判明しました。

1. **モデル属性の定義**:
   - OpenClawは `/v1/models` レスポンスをパースし、各モデルの `input` プロパティを確認します。
   - `input: ["text", "image"]` のように `"image"` 属性が付与されているモデルでのみ、画像送信ロジックが有効化されます。
   - 現状のアダプターは `object: "model"` のみを返しており、`input` フィールドが欠落しているため、OpenClaw側で「このモデルは画像を送れない」と判断されている可能性があります。

2. **モダリティごとのモデル選択 (`imageModel`)**:
   - OpenClawには `imageModel` という設定があり、画像が含まれる場合に特定のマルチモーダルモデルへ自動的に切り替える機能があります。

### 4. 根本原因の集約

現在、画像が正常にバイパス・認識されない原因は以下の3点に集約されます。

1. **[致命的] `src/converter.js` の `extractText` 不具合**:
   - 最新のメッセージに `type: "image_url"` のブロックが含まれていても、この関数が `"text"` 以外をすべて除外しているため、アダプターが画像情報を完全に無視してしまいます。
   - これにより、Gemini CLI に画像パスが渡されず、単なるテキストチャットとして処理されています。

2. **[機能解放] モデル能力フラグの欠落**:
   - アダプターの `/v1/models` がモデルの能力（`input: ["text", "image"]`）を返していないため、OpenClaw側で画像送信機能が制限されている可能性があります。

3. **[履歴処理] `PRUNED_HISTORY_IMAGE_MARKER` への非対応**:
   - OpenClawの `history-image-prune.ts` により、過去のメッセージ内の画像は `[image data removed - ...]` という文字列に置換されます。
   - アダプターの `server.js` にある `mediaAttachedPattern`（正規表現）はこのマーカーに対応していないため、履歴から画像を抽出・復元することができません。

### 5. 課題の整理（Docker環境）
- `/tmp/openclaw/uploads/` へのアクセス不整合については、バックログにて Docker ボリュームマウントによる解決を計画。
- パス解決自体よりも、上記「画像ブロックの消失」が現在の最大の問題です。

【追加の議論と検証ループ】
- **本質的課題の再定義**: ユーザーの指摘通り、最大の問題は「最新のターンの画像が見えない」こと。これはアダプターの入力パース不足（画像ブロック無視）が主因。履歴の置換対応は副次的だが、長期の対話には必須。

【最終的な事実】
- `src/converter.js` L9-16: `p.type === 'text'` 以外をフィルタリングしているため、マルチモーダル入力に対応できていない。
- `analysis_target_openclaw_stable`: OpenClaw は内部的に画像を ContentBlock として管理しており、アダプターにもその形式で送出している。

## 6. [2026-03-15] Web UI における画像ブロック (`image_url`) 対応の実装

### Discussion & Investigation
- **課題**: Telegram などのボット経由では `[media attached: ...]` というテキストマーカーで画像が送られてくるが、OpenClaw Web UI から送信された画像は OpenAI 互換の `image_url` オブジェクトとして `content` 配列に含まれる。これまでのアダプターはテキストマーカーのみを抽出対象としていたため、Web UI 経由の画像が完全に無視されていた。
- **調査事実**: `src/server.js` における `lastUserMsg.content` が配列である場合、その中の `type: 'image_url'` 要素をスキャンする必要があることを特定。

### Implementation
- **対象ファイル**: `src/server.js`
- **修正内容**: `mediaPaths` の抽出ロジックに、`lastUserMsg.content` が配列の場合のループ処理を追加。`image_url.url` から `file://` プレフィックスを除去して絶対パスを取得し、`mediaPaths` に追加するコードを実装した。
- **副次的修正**: パス抽出時のデバッグログ出力を強化し、パースの可視性を向上。

### Debugging & Verification
- **結果**: Web UI から画像を添付してメッセージを送信した際、アダプターのログに `image_url path added: "/workspace/..."` と出力され、Gemini CLI に正しく画像パスが渡されることを確認。これにより Web UI でのマルチモーダル対応を完了した。
