### 調査レポート：Persistent Runner（常駐型ランナー）への移行とレイテンシの極限排除

【調査の道筋（仮説と検証のトレイル）】
- **仮説1**: 現在の SSoT 6.4 における遅延は、Node.js の起動時間（ウォームアップ不足）が原因である。
- **検証1**: `logs/adapter.log` を確認。子プロセスの `spawn` 自体は数ミリ秒で完了し、さらに IPC で `run` メッセージを送ってから実際に処理が始まるまでも極めて高速（SSoT リハイドレートは 1ms）であることを確認。
- **事実の発見1**: **Node.js レベルのウォームアップは既に成功している。** しかし、実際のトークン出力開始までに依然として 18〜20 秒（うち内部初期化に 12 秒以上）を要している。

- **仮説2**: 遅延の主因は Gemini CLI 内部の初期化、特に MCP サーバーの起動にある。
- **検証2**: `logs/mcp.log` を確認。リクエストのたびに MCP サーバーが新規起動しており、その初期化（ツールのロード等）に **約 6 秒** 要している事実を時系列ログから特定。
- **事実の発見2**: 現在の「使い捨て（Disposable）」ランナーモデルでは、Node プロセスを事前に起動しても、Gemini CLI の `runNonInteractive` を呼ぶたびに MCP サーバーの再起動が発生し、これが「起動税」として残存している。

【追加の議論と検証ループ】
- **議論/指摘1**: 「現状のウォームアップは、開発初期（Session 8 等）のウォームアップと全く同じなのか？」
- **新仮説1**: 開発初期にはプロセスの再利用（Persistent）が行われていたが、どこかのタイミングで使い捨て（Disposable）に退化した可能性がある。
- **再検証と事実1**: Git 履歴 (`commit 4327fab0`) を確認した結果、**設計当初から「使い捨て」モデルであった**ことが判明。`runner.js` は1回のリクエスト完了後に `process.exit()` しており、`runner-pool.js` は補充のみを行っていた。したがって、現在の挙動は退化ではなく「設計当初からの限界」が MCP 導入により顕在化したものである。

- **議論/指摘2**: 「使い捨てはそのまま、ウォームアップ段階で MCP 起動まで含める（10秒待機）ことはできないか？」
- **検証2**: 
    - A. **徹底ウォームアップ案**: 10秒かけて「完熟」したプロセスを待機させることは可能。しかし、連投時に補充が間に合わない（10秒の壁が再発する）ことと、常に重い初期化をバックグラウンドで回し続けるリソース負荷が課題。
    - B. **常駐化案（推奨）**: プロセスを捨てずに使い回す。これにより 10秒の壁を「最初の1回」だけに隔離できる。懸念される「会話の混入（汚れ）」は、CLI レベルのセッションリセットで解決可能。

- **議論/指摘3**: 「モデルセレクタは Gemini CLI の機能か？ アダプターの実装か？」
- **再検証と事実3**: [server.js](file:///home/heppo/DEV/openclaw-gemini-cli-adapter/src/server.js) L252 を確認。OpenClaw からの `auto` 指定を `auto-gemini-3` に書き換える**「意思決定（セレクタ）」はアダプターの実装**である。Gemini CLI は決定されたモデル名を受け取って実行するエンジンである。

【コードベース・仕様から確認された最終的な事実】
- `src/runner-pool.js` L290-296: プロセスの `exit` をトリガーに新しい Runner を補充している。
- `src/runner.mjs` L148: `runNonInteractive` 完了直後に `process.exit(ExitCodes.SUCCESS)` を実行している。
- `logs/mcp.log`: MCP サーバーがリクエストごとに `Loading OpenClaw tools...` を繰り返している。
- [server.js](file:///home/heppo/DEV/openclaw-gemini-cli-adapter/src/server.js) 内の `Selected model` 決定までは受信から **14ms**。その後の初期化と CLI 内部ルーティングに **約 13 秒** を要している。
