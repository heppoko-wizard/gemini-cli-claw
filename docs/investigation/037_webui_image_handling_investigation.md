# 調査レポート：WebUI画像表示問題 (Base64データのデコードとパス受け渡し)

## 1. 現状の把握
OpenClaw WebUIから送信される画像データは、`adapter_last_req.json` の解析により、`data:image/jpeg;base64,...` という Data URI 形式のオブジェクトとして届いていることが判明している。
現在のアダプター（`src/server.js`）は、この形式を検知するとスキップするように実装されており、Gemini CLI (`@google/gemini-cli`) に画像データが渡っていない。

## 2. 調査のステップと事実の整理

### Phase 1: 構成要素の再定義と事実確認
- **Gemini CLI の定義**: 本プロジェクトで使用しているのは `@google/gemini-cli` パッケージである。`gogcli` は無関係である。
- **画像受け渡しロジック**: `src/runner.mjs` にて、`mediaPaths` 配列に格納されたローカルファイルの絶対パスを `@絶対パス` 構文としてプロンプトの先頭に注入し、さらに `WorkspaceContext` に `addReadOnlyPath` として登録することで画像入力を実現している。
- **ユーザー指示の再確認**: アダプター側の「ローカルに保存し、そのパスを渡す」という画像受け渡しロジックは絶対に変更不可能な設計上の制約である。

### Phase 2: 事実の発見（Fact Finding）

【調査の道筋】
- **検証**: `src/server.js` の L285-309 （WebUI / image_url オブジェクト形式のセカンダリスキャン）における処理の確認。
- **事実**: 
  - L292-295 にて `url.startsWith('data:')` の場合に `continue`（スキップ）している。
  - L297-303 にて `file://` 形式または絶対パス形式の場合のみ `mediaPaths` に追加している。
- **解決の道筋（事実に基づく）**:
  - `data:` 形式を検知した際、`src/media.js` を用いてデコードし、ローカル（`/tmp` 等）に保存する。
  - 生成された絶対パスを `mediaPaths` 配列に追加する。
  - これにより、`src/runner.mjs` 側の既存ロジックが変更なしで画像を Gemini CLI へ引き渡すことが可能となる。
